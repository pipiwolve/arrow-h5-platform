## 摘要

箭牌卫浴空间的智能化：小度、卫浴柜、小程序三个入口控制马桶、浴霸、浴缸、毛巾架。RTC 管一句话就动的指令，DuMate 管数据统计与多步任务。已实测 80 句指令、50 条问答、10 类场景；时延与识别率为目标值。

# 箭牌智能卫浴：客户场景与价值案例

> 2026-11-02 · 签约中 · 技术验证完成，样板间未落地

## 客户背景

箭牌家居集团 1994 年创立于佛山，2022 年在深交所主板上市，旗下有 ARROW 箭牌、FAENZA 法恩莎、ANNWA 安华三个品牌，产品覆盖卫生陶瓷、龙头五金、浴室家具、浴缸浴房、瓷砖与智能坐便器，经销网络覆盖全国。

智能马桶、浴霸、浴缸、毛巾架、智能卫浴柜都已联网，具备设备控制、场景创建、设备列表三类接口。短板不在硬件，在入口和调度：设备各自为政，用户要记四套操作逻辑。

## 一、场景与需求

卫浴是家里设备密度最高的空间。一次完整使用会跨三四个设备：进门预热、如厕、沐浴、烘干、离场。

客户要三件事：

1. **小程序与硬件更智能**——现有小程序入口深，马桶和卫浴柜停在单机功能，缺一个听得懂人话的调度层。
2. **接入小度生态**——小度生态对外开放，箭牌设备可直接接入，借小度的家庭入口和语音习惯获客，不必只靠自有 App。
3. **一个能给人看的样板间**——用于行业演讲、展会、渠道招商，设备要真的会动。

## 二、客户要做什么、业务目标

| 场景 | 用户要完成的事 | 现在的操作 |
| --- | --- | --- |
| 如厕 | 开盖、冲水、夜灯、座温 | 遥控器或 App，逐项点 |
| 沐浴前 | 浴霸取暖、浴缸放水、毛巾预热 | 墙面开关 + 浴缸面板 + 毛巾架面板 |
| 沐浴后 | 关浴霸、换气、烘干、排水 | 回到三处逐台关闭 |
| 日常 | 查参数、查故障、报修 | 翻说明书 PDF 或打客服 |
| 离场 | 关闭所有设备 | 逐台检查，容易漏 |

业务目标分五层：产品从单品升级为空间；渠道把样板间复制到门店与楼盘；服务把咨询与自查前移；生态接入小度拿家庭入口；品牌形成可对外讲的案例。

## 三、Before

**入口散。** 马桶用遥控器和 App，浴霸用墙面开关，浴缸用机身面板，毛巾架一块独立面板，卫浴柜屏只做显示。一次沐浴前后要在四个地方操作。

**操作深。** 控制大冲要在 App 里选房间、点设备、进二级面板、再点大冲，四步。

**知识靠翻。** 三款主力产品（箭牌 AKB1357、法恩莎 FLM0814S、安华 NiL125）的电子说明书合计 100 页，查「加一次盐能用几次」只能一页页翻。

**任务断。** 语音停在单动作。「洗完澡把湿气弄掉」接不住——要关浴霸、开换气、开烘干，还要等时间。

**展示靠讲。** 对外只能 PPT 加视频，客户看不到设备真的联动。

## 四、After

### 4.1 入口统一

小度（跨空间）、智能卫浴柜（近场）、小程序（远程）三个入口共用一套设备语义。同一台马桶在三处同名同状态，按品牌隔离，不会把法恩莎的参数答成箭牌的。

小度侧走标准接入，箭牌设备直接进小度生态，不需要为每个品类单独造入口。

### 4.2 快慢两条链路

**RTC 管快。** 单设备、单动作、参数明确的请求走实时互动实例：开合盖、冲水、夜灯、暖风、除雾、座温水温、浴霸档位、浴缸进出水、毛巾架烘干。说完就动。

**DuMate 管复杂。** 数据统计、跨设备编排、需要等待或查询的任务，路由到 DuMate 执行后返回结果。典型几类：

- 「这个月主卫马桶用了多少次、哪天用得最多」
- 「滤芯还能用多久，什么时候该换」
- 「最近一周有没有故障记录，报修到哪一步了」
- 「洗完澡把浴霸关了、换气开十分钟、毛巾架烘干一小时」

### 4.3 DuMate 怎么接

用 Agent API 接，不改客户系统。

1. 服务端判断意图属于统计或复杂任务，`POST /sessions` 建会话，绑定预置 Agent（挂设备统计、耗材、故障、报修四个 Skill），凭证放 Vault，由服务端持有。
2. 先 `GET /sessions/{id}/events/stream` 订阅 SSE，再 `POST /sessions/{id}/events` 发 `user.message`。顺序反了看不到过程。
3. 执行结果从 SSE 的消息片段取文本或表格；带文件的走 `file-export`，再用 `/artifact/path-map` 换成临时地址，交给柜屏或小程序渲染。
4. 会话按「用户 + 家庭」复用，超时或 `server.disposed` 按连接失败处理并重连。

客户保留入口、账号和权限，DuMate 只做执行，不碰客户业务系统。

### 4.4 指标

**已实测（箭牌 UAT，2026-10）**

| 指标 | 结果 |
| --- | --- |
| 客户指令集 | 80 句全过，大小冲未串 |
| 真实设备控制 | 5 类指令有真实回执 |
| 场景覆盖 | 10 类全过 |
| 产品问答 | 50 条全过（箭牌 23、安华 12、法恩莎 11、跨型号 4） |
| 失败判定 | 设备离线记 FAILED，不误记成功 |
| 操作步数 | 4 步 → 1 句 |
| 查询路径 | 100 页说明书 → 1 句问答 |

**目标值（未实测）**

| 指标 | 目标 |
| --- | --- |
| 唤醒到首响 / 单动作端到端 | ≤1 秒 / ≤2 秒 |
| 指令识别 / 问答准确率 | ≥95% / ≥90% |
| 误触发率 | <1% |
| 复杂任务首包 / 完整返回 | ≤3 秒 / ≤30 秒 |
| 三入口一致性 | 100% |

链路 0.05 元/分钟；10 万台口径下每台每年约 0.18 元，年链路费 1.83 万元。

## 六、口径

1. 1.3 秒、95%、90% 是目标或方案口径，不是箭牌实测。
2. 「三入口」目前只有 H5/小程序形态，小度和柜屏未接。
3. 客服成本、转化率、客流没有基线，不写百分比。
