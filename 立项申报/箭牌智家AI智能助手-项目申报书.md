## 二、项目背景与必要性

### 2.1 行业背景

智能卫浴的单品智能化已经完成：马桶能自动开盖、座圈能加热、浴霸能恒温、毛巾架能烘干。但单品之间的协同没有跟上。一个卫生间里四五台智能设备，四五个控制入口，用户学一遍就要记住每个设备的操作逻辑。

行业里的语音方案大多停在「单品 + 单指令」。设备一多，指令就碎；场景一复杂，语音就退化成遥控器的替代品。真正的难点不在识别，在任务：用户说的是「洗完澡把湿气弄掉」，不是「关浴霸、开排风、开毛巾架烘干」。

### 2.2 企业现状

箭牌家居集团 1994 年创立于佛山，2022 年深交所主板上市，旗下箭牌、安华、法恩莎三个品牌，产品覆盖卫生陶瓷、龙头五金、浴室家具、浴缸浴房与智能坐便器，经销网络覆盖全国。智能马桶、浴霸、浴缸、毛巾架、智能卫浴柜均已联网，具备设备控制、场景创建、设备列表三类接口能力；现有小程序功能齐全，但入口层级深，语音只覆盖少量单品功能。

企业当前缺三样东西：统一的设备语义、能把数据统计与复杂任务执行完的调度层、一个能对外呈现的实体场景。

### 2.3 必要性

**用户侧。** 卫浴空间的使用者跨度大，老人和儿童对多层菜单最不友好。一句话完成一串动作，是这类人群真正能用的智能。

**产业侧。** 智能家居的竞争已经从单品功能转向场景体验。谁能把跨设备任务做稳，谁就能把「智能」卖出溢价。

**生态侧。** 家庭入口正在被音箱、屏、车机分流。小度生态对外开放，箭牌设备可直接接入，不必只依赖自有 App 拉新。

**示范侧。** 目前行业内缺少可参观、可复现的智能卫浴样板。建一个真实可用的空间，比做十页 PPT 更有说服力。

## 三、建设目标与考核指标

### 3.1 总体目标

建成一套面向卫浴空间的多入口智能交互系统，覆盖智能马桶、浴霸、浴缸、毛巾架和智能卫浴柜；形成实时指令与复杂任务两条链路；建成一个可对外展示、可复制到门店的实体样板间。

### 3.2 具体目标

| 方向 | 目标 |
| --- | --- |
| 多入口 | 小度、卫浴柜屏、小程序三入口控制同一套设备，状态一致 |
| 实时响应 | 单动作指令端到端 ≤2 秒，唤醒到首响 ≤1 秒 |
| 任务执行 | 5 类典型复杂任务全流程跑通，单任务 ≤30 秒 |
| 识别准确 | 设备指令识别 ≥95%，误触发 <1% |
| 安全可控 | 高危指令 100% 二次确认，操作 100% 留痕 |
| 可展示 | 6 分钟参观动线，连续演示 2 小时无中断 |
| 可复制 | 输出门店版本配置清单与部署手册 |

### 3.3 考核方式

| 指标 | 目标值 | 验收方式 |
| --- | --- | --- |
| 单动作响应时延 | ≤2 秒 | 现场 20 次计时，取中位数 |
| 唤醒到首响 | ≤1 秒 | 现场计时 |
| 指令识别准确率 | ≥95% | 客户指令集全量回归 |
| 误触发率 | <1% | 1000 条非控制语句 |
| 复杂任务完成率 | ≥90% | 5 类任务各 20 次 |
| 高危拦截 | 100% | 高危清单逐条验证 |
| 三入口一致性 | 100% | 同一指令三入口各执行一次 |
| 连续演示 | 2 小时无中断 | 布展前彩排记录 |

## 四、建设内容

### 4.1 三个入口

**小度。** 作为跨空间入口，放在客厅或玄关。用户不进卫生间也能启动预热、烘干、放水。小度生态可直接接入，箭牌设备走标准接入进生态，再完成意图对接与状态同步。

**智能卫浴柜。** 柜屏作为近场入口，承担触控与语音两种交互，同时显示设备状态和任务进度。它是样板间里最主要的视觉焦点。

**小程序。** 保留远程控制与文字输入。出差在外也能看设备状态、启动任务、接收提醒。

三个入口共用一套设备语义表。同一台马桶在小度里叫「主卫马桶」，在柜屏和小程序里必须是同一个名字、同一个状态。

### 4.2 四类设备

| 设备 | 实时指令 | 数据统计与复杂任务 |
| --- | --- | --- |
| 智能马桶 | 开合盖、冲水、夜灯、座温、水温、暖风 | 按作息预热、使用习惯提醒、滤芯与耗材 |
| 浴霸 | 开关、取暖档位、换气、照明 | 沐浴前后联动、湿度触发、定时 |
| 浴缸 | 进水、排水、水温、保温 | 放水提醒、泡澡场景、儿童安全水位 |
| 毛巾架 | 烘干、定时、档位 | 梅雨季连续烘干、离家关闭 |

### 4.3 两条链路

**实时链路（RTC）。** 单设备、单动作、参数明确的请求，走实时互动实例。音频与字幕直连房间，服务端只做授权、帧解析和指令下发。

**任务链路（DuMate）。** 数据统计、汇总报表、多设备有先后、需要等待或查询的请求，路由到 DuMate 执行后返回。接入用 Agent API：建 Session、绑 Agent、订阅 SSE、发消息、取结果与产物。执行过程向用户回执，超时给中间状态。

两条链路之间设一个分流判定，不靠模型自由发挥。判定规则写进配置，可审计、可调整。

### 4.4 安全与审计

- 指令白名单：不在表内的动作不下发。
- 风险分级：高危动作二次确认，中风险选设备后执行。
- 设备消歧：多台同类设备出选择卡，不猜。
- 结果校验：设备离线记失败，不记成功，不自动重试。
- 全量审计：入口、操作人、时间、设备、动作、结果。

### 4.5 样板间与展示

样板间按真实卫浴布局建设，包含洗漱区、如厕区、沐浴区。配置演示模式（一键复位）、状态可视（柜屏总览）和降级路径（断网提示与备用话术）。

配套交付一份 6 分钟讲解动线、一套行业演讲材料、一份门店复制配置清单。

## 五、技术路线与创新点

### 5.1 技术路线

**入口层。** 小度设备、柜屏、小程序三种客户端，统一调用服务端会话与设备接口。

**实时层。** 百度智能云 RTC 互动智能体，集成 ASR、TTS、大模型与知识库。服务端用 BCE v3 签名建实例，lickey 激活后开放业务。

**任务层。** DuMate Agent 负责数据统计、任务拆解、步骤执行与结果回执。通过 Agent API 接入：`POST /sessions` 建会话并绑定 Agent，先订阅 `events/stream` 再发 `user.message`，结果从 SSE 与 `artifact/path-map` 取回。

**设备层。** 箭牌 IoT 提供设备列表、控制与场景接口；小度 IoT 承接生态侧设备。两条通道按归属选择。

**安全层。** 独立于模型之外的闸门服务，所有下发指令必须过闸。

### 5.2 创新点

**一、按任务时长分流，而不是把所有请求丢给大模型。** 单动作走实时链路，保证「说完就动」；数据统计与多步任务走 Agent，保证「问得清就查得准、办得完」。两条链路各用所长，时延和成功率都能守住。行业里常见的做法是全部走大模型，结果简单指令慢、复杂任务断。

**二、多入口共用一套设备语义。** 小度、柜屏、小程序不是三套系统，是三个客户端。设备命名、状态、权限在一处定义，避免「同一个马桶三个名字」。

**三、把样板间当成验收现场。** 设备动不动、语音快不快、动线顺不顺，站在房间里就能判断。这让项目验收从文档评审变成现场体验，也让它天然具备复制到门店的能力。

**四、模型与执行分离的安全设计。** 模型输出只是意图，指令要过白名单、风险分级、消歧和二次确认才可能到达设备。物理设备的误动作代价高，这条隔离不能省。

## 八、效益分析

### 8.1 经济效益

**直接成本可控。** 软件建设 10 万元，链路费每台设备每年约 0.18 元（按 10 万台口径），不构成规模负担。

**展示资产可复用。** 样板间建成后可复制到门店、楼盘、展会，单次搭建成本随复制次数摊薄。

**高端产品支撑。** 智能卫浴空间是高端产品线的差异点，能支撑溢价，而不是陷入单品价格战。

**售后效率。** 耗材提醒、报修自查、远程协助，减少非故障上门。

### 8.2 社会效益

- 降低智能设备的使用门槛，老年用户与儿童受益；
- 用水、用电可见可控，浴缸放水提醒、离家关闭等能力有节能价值；
- 推动智能家居从单品智能走向空间智能，形成可复制的行业样板。

### 8.3 管理效益

- 设备语义统一，跨品牌、跨品类的运营口径一致；
- 操作留痕，售后责任可追溯；
- 演示数据与用户指令数据反哺产品定义。
