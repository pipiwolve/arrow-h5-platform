## 摘要

箭牌家居与百度智能云共建智能卫浴样板：小度、智能卫浴柜、双方小程序三个入口，联动马桶、浴霸、浴缸、毛巾架。RTC 承接低延时指令，DuMate 承接数据统计与多步任务。交付包含一场行业演讲和一个实体样板间。建设费 10 万元，首年链路约 1.83 万元。

## 二、立项背景

### 2.0 客户背景

箭牌家居集团 1994 年创立于佛山，2022 年深交所主板上市，旗下 ARROW 箭牌、FAENZA 法恩莎、ANNWA 安华三个品牌，产品覆盖卫生陶瓷、龙头五金、浴室家具、浴缸浴房、瓷砖与智能坐便器，经销网络覆盖全国。

智能马桶、浴霸、浴缸、毛巾架、智能卫浴柜均已联网，设备控制、场景创建、设备列表三类接口已经开放。硬件不缺，缺的是入口和调度。

### 2.1 卫浴空间里有三个断点

**设备断点。** 智能马桶、浴霸、浴缸、毛巾架分别联网，也分别有控制方式：马桶用遥控器和 App，浴霸用墙面开关，毛巾架一块独立面板，浴缸要走到旁边按键。用户想「洗完澡把浴霸关了、毛巾架开上、浴缸放水」，得做四件事。

**入口断点。** 箭牌有小程序，小度有音箱和屏，卫浴柜有一块屏。三个入口各说各话，同一台设备在不同入口里的名字、状态、可控范围不一致。

**任务断点。** 现有语音能力多半停在「开盖」「冲水」这种单动作。真正有价值的是任务：按作息预热座圈、梅雨季连续烘干、滤芯到期提醒、报修前先自查。这些需要跨步骤、跨设备、跨时间，靠一句指令映射做不到。

### 2.2 为什么现在做

第一，实时语音的体验线过了及格线。RTC 方案口径下端到端时延 1.3 秒、打断 0.8 秒以内，用户说完就能看到设备动作，不会出现「说完了等三秒」的尴尬。

第二，任务型 Agent 可用了。DuMate 能把「统计本月各设备使用次数、算出滤芯剩余寿命、生成一张用水报表」这类请求拆成步骤执行，再把结果返回给入口，而不是让用户自己去翻数据。

第三，小度生态是可直接接入的。箭牌设备按标准方式接入小度，就能用小度的音箱和屏控制，不必为每个品类单独造入口，也不用只靠自有 App 拉新。

第四，客户今年有明确的展示需求：一场行业演讲，一个能走进去的样板间。这给了项目一个硬时间点，也给了验收一个看得见的标准。

### 2.3 项目定位

这不是给箭牌再做一个语音助手。

它要证明三件事：同一套设备，三个入口，体验一致；一句话对应一个动作的走实时链路，数据统计和多步任务走 DuMate；这套能力可以搬进门店、展会和下一个楼盘样板间。

样板间不是演示道具，是这套能力的验收现场。设备不动、语音不响、场景不连贯，站在里面一眼就能看出来。

## 三、建设目标

### 3.1 总目标

在箭牌卫浴空间内建成一套多入口、跨设备的智能控制与任务执行能力，并以实体样板间和行业演讲完成对外呈现。

### 3.2 分目标

| 方向  | 目标                   | 判定方式            |
| --- | -------------------- | --------------- |
| 快   | 单动作指令说完即动，端到端 ≤2 秒   | 现场计时，取 20 次中位数  |
| 繁   | 数据统计与多步任务可拆解、可执行、可回执 | 5 个典型任务脚本全部跑通   |
| 通   | 小度、柜屏、小程序三入口控制同一套设备  | 同一指令在三个入口各执行一次  |
| 准   | 设备指令识别 ≥95%，误触发 <1%  | 指令集回归 + 非控制语句测试 |
| 稳   | 连续演示 2 小时不出中断        | 布展前压力彩排         |
| 可看  | 一次完整参观动线 6 分钟，无需人工干预 | 讲解脚本走查          |

### 3.3 演示指标

样板间对外开放时，以下指标决定观感，需要在布展前锁定：

- 唤醒到响应不超过 1 秒（本地唤醒 + 云端首包）。
- 一句指令到设备动作可见不超过 2 秒。
- 复杂任务的首句反馈不超过 3 秒，全部完成不超过 30 秒。
- 断网或设备离线时，屏上有明确提示，不出现「说了没反应」。

## 四、范围与边界

### 4.1 本期做什么

**入口层。** 小度音箱/屏接入、智能卫浴柜屏接入、箭牌智家小程序与百度侧小程序入口，三个入口共用一套设备语义和状态。

**实时层。** RTC 互动智能体承接单动作指令：开合盖、冲水、夜灯、暖风、除雾、水温与座温调节、浴霸开关与档位、浴缸进水与排水、毛巾架烘干。

**任务层。** DuMate 承接数据统计与多步任务：设备使用次数、用水用电、耗材剩余、故障与报修进度、沐浴前后联动、按作息预热。复杂请求由服务端路由过来，执行完把结果和产物返回入口。

**安全层。** 沿用 H5 版本已经跑通的四道闸门：指令白名单、风险分级、设备消歧、二次确认；全量审计留痕。

**展示层。** 样板间空间设计配合、设备联调、演示脚本、讲解动线、行业演讲材料。

### 4.2 本期不做

**不替代箭牌现有 IoT 平台。** 设备注册、固件、生产凭证仍归箭牌。我们只调用它已经开放的接口。

**不做全屋家电。** 范围限定在卫浴空间：马桶、浴霸、浴缸、毛巾架、卫浴柜。空调、照明、门锁不在本期。

**不做健康诊断。** 座圈温度、如厕时长这类数据可以用于提醒，但不能输出诊断结论，也不能承诺健康效果。

**不做量产版本。** 本期交付样板间与小范围可用版本。量产要过的认证、成本、售后体系另议。

**不承诺销量。** 样板间能带来多少客流、多少转化，取决于箭牌的门店运营，不在本项目的考核范围。

### 4.3 依赖客户提供

| 事项 | 用途 | 不到位的影响 |
| --- | --- | --- |
| 设备清单与指令集 | 指令映射 | 只能演示预置的几条 |
| IoT 生产凭证与测试家庭 | 真实下发 | 停在 UAT |
| 小度接入所需账号与设备配置 | 生态打通 | 小度入口无法演示 |
| 卫浴柜屏的硬件规格与系统版本 | 柜屏入口 | 只能退化成平板演示 |
| 样板间场地、水电、网络 | 布展 | 工期顺延 |
| 品牌口径与产品资料 | 知识问答 | 答错参数 |
| 演讲场合与听众构成 | 内容定制 | 讲稿偏技术或偏营销 |

## 五、技术方案

### 5.1 分层结构

**入口层。** 三种形态：小度设备（语音入口）、卫浴柜屏（近场触控 + 语音）、小程序（远程与文字）。三者不各自实现一套逻辑，统一走服务端的会话与设备接口。

**实时交互层。** 百度智能云 RTC 互动智能体。ASR、TTS、大模型、知识库在同一实例内，音频与字幕直连房间，不经过业务服务器。服务端负责建实例、授权激活和帧解析，密钥不出服务进程。

**任务编排层。** DuMate Agent，通过 Agent API 接入。服务端判断请求属于统计或复杂任务后建 Session，绑定预置 Agent（挂设备统计、耗材、故障、报修等 Skill），先订阅 SSE 再发消息，结果与产物返回给入口。客户保留账号、权限和业务系统。

**设备控制层。** 箭牌 IoT（设备列表、控制、场景）与小度 IoT。两条通道按设备归属选择，不重复下发。

**数据与运营层。** 会话记录、指令审计、失败原因、常用指令排行。用于迭代和布展调优。

### 5.2 快慢怎么分

这是本方案最关键的一条规则。分错了，要么慢，要么乱。

| 请求特征 | 走向 | 例子 |
| --- | --- | --- |
| 单设备、单动作、参数明确 | RTC 实时 | 打开夜灯、来个大冲、浴霸二档 |
| 数据统计、汇总、报表 | DuMate | 本月马桶用了几次、用水用电统计、故障 Top |
| 多设备、有先后顺序 | DuMate | 洗完澡关浴霸、开毛巾架烘干、浴缸排水 |
| 需要等时间或条件 | DuMate | 明早七点预热座圈、湿度超过 80% 开烘干 |
| 需要查信息再决定 | DuMate | 滤芯还能用多久、这个型号支持不支持除臭 |
| 含糊、多目标 | 先澄清，再分流 | 把卫生间弄暖和点 |

实时层判断不了的请求，转任务层，不在实时层硬猜。任务层执行中可以向用户追问一次，但不能连续追问，否则体验比手动还差。

### 5.3 安全闸门

沿用 H5 版本已经验证的四道检查：

1. **白名单。** 不在指令表里的动作一律不下发。
2. **风险分级。** 中风险（开关、冲水、夜灯）选唯一设备后直接下发；高风险（水温上限、浴缸大量进水、总电源）必须二次确认。
3. **设备消歧。** 多台同类设备时出选择卡，按 1、2 区分，不猜。
4. **结果校验。** 平台返回 200 但设备离线时记失败，不记成功，不自动重试。

审计记录操作人、入口、时间、设备、动作、结果。样板间演示期间同样开启，便于复盘。

### 5.4 样板间形态

空间按真实卫浴布局：洗漱区、如厕区、沐浴区。柜屏装在洗漱区，小度放在客厅或玄关作为跨空间入口，马桶、浴霸、浴缸、毛巾架按真实安装方式布置。

技术上需要三样东西：

- **演示模式。** 一键复位所有设备到初始状态，讲解员不用手动收拾。
- **状态可视。** 柜屏上能看到每台设备的当前状态，避免「说了但看不出来」。
- **降级路径。** 网络或设备异常时，屏上给明确提示，讲解员有一套备用话术。

### 5.5 演讲与动线

参观动线按「进门—洗漱—如厕—沐浴—离场」设计，每站一句主指令、一个可见动作、一句价值解释。全程 6 分钟，讲解员不碰任何开关。

演讲内容围绕三件事：卫浴空间为什么需要统一入口、快慢两条链路怎么分工、这套东西怎么复制到门店和楼盘。不堆参数，现场演示为主。

## 九、预期效益

### 9.1 对箭牌

**产品叙事。** 从「智能马桶」升级到「智能卫浴空间」，这是高端产品线能讲清楚的差异点。

**渠道工具。** 样板间可以直接复制到门店和楼盘，成为招商与销售的现场道具。

**入口扩展。** 借小度进家庭，降低只靠自有 App 的获客压力。

**服务能力。** 保养提醒、报修自查、耗材更换，把售后从被动接单变成主动触达。

### 9.2 对百度

**行业标杆。** 智能家居是 RTC 与 DuMate 组合的典型场景，箭牌是可对外讲的案例。

**生态协同。** 小度、RTC、DuMate 三条产品线在同一个客户里落地，验证组合打法。

**可复制性。** 卫浴空间的方案可以平移到厨房、阳台、酒店客房。

### 9.3 可观测指标

本期只埋点、出数据，不承诺具体增幅：

- 样板间单次参观的完整演示率与停留时长；
- 演示后留资或预约量；
- 三入口的指令成功率与失败原因分布；
- 复杂任务的完成率与中断率；
- 高频指令 Top 10，反哺产品定义。

| 签约与场地工期冲突 | 展览时间不可改，布展被压缩 | 第 2 周锁定图纸与设备，施工与内容并行 |
| 小度接入排期 | 生态入口无法按期演示 | 第 2 周完成账号与设备配置；排期不足时先用柜屏 + 小程序双入口，小度顺延 |
| 现场网络不稳 | 语音断续、演示翻车 | 专线 + 本地缓存 + 降级话术，彩排按断网场景演练 |
| 多品牌设备命名不一致 | 指令打错设备 | 统一设备语义表，按 appPlatform 隔离 |
| 任务层执行超时 | 用户等待后无结果 | 首句即时反馈，超时给中间状态，20 秒未完成主动收口 |
| 模型幻觉越权 | 高危动作误执行 | 白名单 + 二次确认，模型输出不直接下发 |
| 样板间被当成交付终点 | 量产预期落空 | 立项书明确「样板间 + 小范围可用」，量产另议 |
| 演讲与技术脱节 | 现场效果好、客户内部推不动 | 讲稿同时准备业务版与技术版，展后出一页纸复制清单 |

## 十一、结论与建议

建议立项，理由有三条。

**场景成立。** 卫浴是家里设备密度最高、动作最连贯的空间，用户对「一句话搞定」有真实需求，不是想象出来的。

**技术够用。** 实时链路已经在箭牌 UAT 上跑通真实设备控制，复杂任务有 DuMate 承接，小度生态可直接接入。三条腿都有，缺的是把它们装进一个房间。

**交付可验。** 样板间和演讲是硬验收：设备动不动、语音快不快、动线顺不顺，站在里面就知道。

建议按 12 周推进，第 2 周冻结范围与小度路径，第 10 周完成连续演示彩排。签约未落地前，先做不与商务绑定的技术准备：设备语义表、任务脚本、柜屏适配原型。
