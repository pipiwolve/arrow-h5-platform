## 摘要

按当前代码整理。改参数的位置只有四处：`.env`、`config/scenario.json`、设备名单 JSON、百度「大模型实时互动」控制台。人设全文和函数填表见 `产品文档/后台控制台交付配置.md`。本文只列参数名、是否必填、当前非机密默认值。

# 配置参数清单

密钥、AppID、AK、SK、license、IoT token、统计 Key 只写在本机 `.env`，不要写进本文，也不要提交仓库。

## 1. 最少要填的

通话能建起来，需要下面六项。缺任何一项，页面可以打开，输入框保持关闭。

| 参数 | 位置 | 作用 |
| --- | --- | --- |
| `BRTC_APPID` | `.env` | 互动应用 |
| `BRTC_AK` | `.env` | 建实例签名 |
| `BRTC_SK` | `.env` | 建实例签名 |
| `BRTC_LICKEY` | `.env` | 进房后的激活帧 |
| `BRTC_DEVID` | `.env` | 激活计次用的固定设备号 |
| 自定义角色人设 | 百度控制台 | 建实例不传人设，没绑角色就没有业务提示词 |

要打到真实设备，再加：

| 参数 | 位置 |
| --- | --- |
| `IOT_MODE=real` | `.env` |
| `IOT_BASE_URL` | `.env` |
| `IOT_TOKEN` | `.env` |
| `iot.homeId` | `config/scenario.json` |

要答产品问题，控制台还要绑知识库模板 `arrow_product_kb`。要做调用次数和使用时长，再填 `TOPIC_ADAPTER_URL` 和 `TOPIC_API_KEY`。

## 2. 环境变量 `.env`

照 `.env.example` 复制。命令行里的同名变量会覆盖文件。`IOT_FIXTURE` 和 `BRTC_DIRECT` 只认进程环境变量。

| 参数 | 必填 | 当前默认 | 说明 |
| --- | --- | --- | --- |
| `PORT` | 否 | `8900` | H5 监听端口。Agent API demo 用 8898，不要撞车 |
| `BRTC_APPID` | 是 | 空 | 控制台「大模型实时互动」里的互动应用。获取页：`https://console.bce.baidu.com/rtc/#/rtc/interaction` |
| `BRTC_AK` | 是 | 空 | 百度智能云 AK。只留在 Node，不发给浏览器。获取页：`https://console.bce.baidu.com/iam/#/iam/accesslist` |
| `BRTC_SK` | 是 | 空 | 与 AK 成对。用来给 `generateAIAgentCall` 做 BCE v3 签名 |
| `BRTC_LICKEY` | 是 | 空 | license 的 key 列，不是资源 id。必须和 AppID 绑定，且与 AK/SK 同一账号。获取页：`https://console.bce.baidu.com/rtc/#/rtc/resource` |
| `BRTC_DEVID` | 否 | `DEVID-ARROW-H5-0001` | 激活按 licenseKey + appId + deviceId 计次。换号会反复消耗额度 |
| `BRTC_API_HOST` | 否 | `https://rtc-aiagent.baidubce.com` | 建实例和停实例的主机。示例网关 `ai.agent.kaywang.cn` 对本 AppID 会回 No such app |
| `BRTC_INSTANCE_TYPE` | 否 | `VoiceChat` | 建实例的 `instance_type` |
| `BRTC_DIRECT` | 否 | 未设置时视为开启 | 代码读了 `!== '0'`，当前没有任何分支使用它 |
| `IOT_MODE` | 否 | 代码缺省是 `mock`；示例文件写的是 `real` | `real` 打箭牌网关。`mock` 在本机起网关 |
| `IOT_PORT` | 否 | `18901` | 只在 `mock` 时监听 |
| `IOT_BASE_URL` | `real` 时必填 | `https://api-uatiot.arrowgroup.com.cn` | 箭牌 IoT 根地址。`mock` 时忽略，改打 `127.0.0.1:IOT_PORT` |
| `IOT_TOKEN` | `real` 时必填 | 空 | 请求头 `Authorization: bearer <token>`。`mock` 时空着会用 `demo-token` |
| `IOT_FIXTURE` | 否 | `demo` | `real` 读 `../箭牌demo打通/iot/devices.real.json`，其他值读 `devices.json`。只认进程环境变量 |
| `TOPIC_ADAPTER_URL` | 统计功能必填 | 空 | 适配层地址，形如 `http://127.0.0.1:8911/v1/chat/completions`。图片地址会把这段末尾换成 `/v1/images/...` |
| `TOPIC_API_KEY` | 统计功能必填 | 空 | 请求头 `Authorization: Bearer <key>`。与 URL 必须同时有，否则统计入口返回 400 |

`GET /api/config` 会告诉页面四件套缺了哪几项，字段名是 `missing`。它不返回 AK、SK、license 和 token。

## 3. 场景文件 `config/scenario.json`

启动时整份读入。缺 `id`、`brand`、`iot`、`agent`、`policy`、`commands`、`repair` 任一顶层字段，进程直接退出。

### 3.1 标识和页面文案

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| `id` | `arrow-brtc-h5` | 场景编号 |
| `brand.product` | `箭牌智能AI助手` | 页面品牌名 |
| `brand.vendor` | `ARROW · BRTC H5` | 页面副标题 |
| `brand.emptyTitle` | `可以直接控制设备，也可以问产品问题` | 对话区空态标题 |
| `brand.emptyDesc` | `箭牌智能AI助手` | 对话区空态说明 |

### 3.2 家庭和 IoT 头

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| `iot.homeId` | `933` | 打到设备列表、控制、建场景的家庭编号。闸门也用它核对 |
| `iot.appPlatform` | `arrow` | 请求头 `appPlatform` |
| `iot.deviceSystemPlatform` | `0` | 请求头 `ArrowDeviceSystemPlatform` |

### 3.3 开场

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| `agent.system` | 空字符串 | 故意留空。人设在控制台，建实例不传 `sceneRoleCfg` |
| `agent.sayhi` | `你好，我是箭牌智家助手。可以直接说想打开或关闭的设备，也可以问产品怎么用。` | 建实例字段 `tts_sayhi`。授权通过后由房间播报 |
| `starters` | 见下表 | 开场示例。点一条等于用户说了这句话，仍走页面分流 |

| 序号 | 当前句子 | 实际去向 |
| --- | --- | --- |
| 1 | 把主卫的浴缸进水打开 | 设备控制，高危确认 |
| 2 | 把主卫坐便器的大冲打开 | 设备控制 |
| 3 | 把主卫镜柜的夜灯打开 | 设备控制 |
| 4 | 我家坐便器不出水了，要报修 | 报修卡 |
| 5 | AKB1357 有哪些功能 | 进房间，走知识库 |

### 3.4 闸门

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| `policy.confirmAtOrAbove` | `H` | 达到该等级要页面确认 |
| `policy.denyAtOrAbove` | `C` | 达到该等级直接拒绝。当前没有规则产出 C |
| `policy.maxTargetsPerCall` | `3` | 一次最多几条指令 |
| `policy.defaultRiskLevel` | `M` | 没有命中风险规则时的等级 |

`riskRules` 按数组顺序，先命中先用。

| when | level | label | basis |
| --- | --- | --- | --- |
| `cmd` = `switch_water_in` | `H` | 浴缸进水阀开关 | 打开主卫浴缸进水 |
| `param` = `switch` | `M` | 常规开关 | 指令表里的开关，可逆 |

### 3.5 指令表 `commands`

模型或原话补出来的 `cmd` 必须在这张表里。`param` 当前都是 `switch`。`appliesTo` 是品类编码：`01` 马桶，`04` 浴缸，`06` 镜柜。

| cmd | 允许的 value | 说明 | appliesTo |
| --- | --- | --- | --- |
| `switch_watering` | `on` | 马桶大冲 | `01` |
| `switch_watering_small` | `on` | 马桶小冲 | `01` |
| `switch_night_light` | `on` / `off` | 夜灯 | `01` `06` |
| `switch_auto_closing` | `on` / `off` | 马桶自动翻盖 | `01` |
| `switch_kicking` | `on` / `off` | 马桶脚触感应 | `01` |
| `switch_auto_oiling_porcelain` | `on` / `off` | 马桶自动润瓷 | `01` |
| `switch_onoff` | `on` / `off` | 开关 | `01` `04` `06` |
| `switch_water_in` | `on` / `off` | 浴缸进水 | `04` |

座温、暖风、除雾、灯光亮度没有指令。不要往这张表外发明 `cmd`，除非箭牌接口已经支持。

### 3.6 报修文案 `repair`

助手不创建工单，只打开 deeplink。

| 参数 | 当前值 |
| --- | --- |
| `repair.deeplink.report` | `arrowhome://repair/create?from=ai_assistant` |
| `repair.deeplink.progress` | `arrowhome://repair/list?from=ai_assistant` |
| `repair.report.note` | 已准备好报修入口。 |
| `repair.report.cardTitle` | 报修 |
| `repair.report.cardBody` | 助手不创建工单。点击后进入箭牌 App 的报修页，填写设备和问题。 |
| `repair.report.linkText` | 打开报修页 |
| `repair.progress.note` | 已准备好进度入口。 |
| `repair.progress.cardTitle` | 报修进度 |
| `repair.progress.cardBody` | 助手不查询工单。点击后进入箭牌 App 的报修记录，查看受理和派工进度。 |
| `repair.progress.linkText` | 查看报修进度 |

页面自己的报修卡文案写在 `public/app.js` 的 `REPAIR_LINKS`，和这里是两份相同的句子。改 deeplink 或卡片文案时两处一起改。

## 4. 设备名单

不在本目录。`scenario.mjs` 按 `IOT_FIXTURE` 读取：

| `IOT_FIXTURE` | 文件 |
| --- | --- |
| `real` | `../箭牌demo打通/iot/devices.real.json` |
| 其他或未设置 | `../箭牌demo打通/iot/devices.json` |

文件不存在时进程退出。闸门用这份名单判断设备在不在家庭、品类支不支持指令。房间名也来自这里，不来自平台返回。

每台设备实际用到的字段：

| 字段 | 用途 |
| --- | --- |
| `deviceName` | 与平台设备号逐字一致。对不上就当不存在 |
| `categoryCode` | `01` / `04` / `06`，用来核对指令是否适用 |
| `deviceTagName` | 选择卡和审计上的名称 |
| `room` | 原话里的「主卫」「客卫」 |
| `capability` | 该设备允许的 `cmd` 列表 |

平台在线状态不写进这个文件。在线与否以设备列表接口为准，而且当前不参与选设备和闸门。

## 5. 百度控制台

这些不在仓库里生效，改完要保存，并结束当前通话再开一通。角色名称不要用「箭牌智家助手」，该名与预置角色重名。人设正文里的自称仍然是这一句。

填表全文在 `产品文档/后台控制台交付配置.md`。这里只列要配的对象和字段。

### 5.1 应用绑定

| 对象 | 标识 | 要确认的字段 |
| --- | --- | --- |
| 互动应用 | 与 `.env` 的 `BRTC_APPID` 同一条 | 已绑定自定义角色；知识库意图模板是 `arrow_product_kb` |
| 知识库意图模板 | 名称 `arrow_product_kb`，ID `10000101` | 模板描述。执行位置保持平台侧检索，不要改成 SDK 消息 |
| 本地建实例 | 不传 | 不要填 `sceneRoleCfg`，不要填 `ragIntentTemplateId` |

### 5.2 人设

控制台自定义角色的整段提示词。结构是三段：`#角色设定`、`#角色形象`、`#要求与限制`。限制共 8 条，规定何时调用 `control_device`、`create_scene`、`open_repair`，以及何时走知识库。

### 5.3 三个 Function

三个的公共字段：

| 字段 | 本版的值 |
| --- | --- |
| 执行前确认 | 否 |
| 是否定时执行 | 否 |
| 请求地址 | 发送 SDK 消息 |

改成 HTTP 后，槽位不再经过 H5，选设备、高危确认和审计都不会发生。

| Function | 参数 | 必填 | 取值 |
| --- | --- | --- | --- |
| `control_device` | `deviceName` | 是 | 家庭设备号，逐字复制 |
| `control_device` | `cmd` | 是 | 第 3.5 节八个指令名之一 |
| `control_device` | `param` | 否 | 固定 `switch` |
| `control_device` | `value` | 是 | `on` 或 `off`。大冲、小冲只能 `on` |
| `control_device` | `say` | 否 | 准备做什么，只用于播报 |
| `create_scene` | `conditionList` | 否 | JSON 数组字符串。线上描述只要求提取时间，例如 `[{"time":"22:00"}]`。没说钟点就留空 |
| `create_scene` | `actionList` | 否 | JSON 数组字符串。每项含 `deviceName`、`cmd`、`param`、`value` |
| `create_scene` | `say` | 否 | 准备设置的时间、设备和动作 |
| `open_repair` | `kind` | 否 | `progress` 表示查进度，其他填 `report`。判断不了就填 `report` |
| `open_repair` | `say` | 否 | 准备打开报修或查询进度 |

描述、例句和参数样例以模板 `892` 的线上原文为准，全文在 `产品文档/后台控制台交付配置.md` 第 3 节。H5 闸门仍要求 `create_scene` 的列表元素带齐 `deviceName`、`cmd`、`param`、`value`。

### 5.4 四个知识库

一个库只上传一个文件。`00` 和 `05` 不上传。

| 知识库 | ID | 上传文件 |
| --- | --- | --- |
| 箭牌AKB1357知识库 | `kbsj9qdy2ks855c` | `产品文档/知识库上传/01-箭牌-AKB1357L-M.md` |
| 法恩莎FLM0814知识库 | `kbsjskp328x52t1` | `产品文档/知识库上传/02-法恩莎-FLM0814S-QL-QM.md` |
| 安华NiL125知识库 | `kbsjskp8ssw3nsm` | `产品文档/知识库上传/03-安华-NiL125L-M.md` |
| 三款对照知识库 | `kbsjskpekffyrjs` | `产品文档/知识库上传/04-三款对照.md` |

切片优先按 Markdown 标题。若平台用默认 500 字、重叠 50 字，要打开切片预览，确认一个问答对没有被切开。

### 5.5 七条知识库意图

每条要填的字段一样：意图名称、意图描述、意图例句、快速匹配短语、挂一个知识库。执行位置不要改成 SDK 消息。

| 顺序 | 意图名称 | 挂的库 | 快速匹配条数 |
| --- | --- | --- | --- |
| 1 | 箭牌AKB1357功能参数 | 箭牌AKB1357知识库 | 4 |
| 2 | 法恩莎FLM0814功能参数 | 法恩莎FLM0814知识库 | 4 |
| 3 | 安华NiL125功能参数 | 安华NiL125知识库 | 5 |
| 4 | 箭牌AKB1357故障保修 | 箭牌AKB1357知识库 | 4 |
| 5 | 法恩莎FLM0814故障保修 | 法恩莎FLM0814知识库 | 4 |
| 6 | 安华NiL125故障保修 | 安华NiL125知识库 | 4 |
| 7 | 三款坐便器对照 | 三款对照知识库 | 4 |

配完后删除旧的三条：型号规格、语音能控制什么、保养或离线与报修说明。

名称最多 40 字，描述最多 1000 字，每条例句最多 40 字。名称只用汉字、英文字母、数字和下划线。描述里不要写「准备查看」，也不要写 900W、电话、故障码这些答案。

## 7. 改完怎么核对

1. `.env` 四件套齐全后，打开页面应自动建连，而不是停在缺项提示。
2. `BRTC_DEVID` 与上次上线相同。
3. `IOT_MODE=real` 时，设备页能拉到家庭 `homeId` 下的设备。
4. 控制台角色名不是「箭牌智家助手」，模板显示 `arrow_product_kb`，三个 Function 都是发送 SDK 消息。
5. 新开一通，问「AKB1357的额定功率是多少」。第一句出现 900W。
