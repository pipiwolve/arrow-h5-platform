## 摘要

- 分支 `experiment/cloud-function-call`，HEAD `c4f29cb`。运行参数 `DEVICE_ROUTE=cloud`、`IOT_MODE=mock`、`IOT_FIXTURE=demo`，家庭 933 共 11 台。
- 语料是 `2026-10-12-客户指令集.md` 的 80 句，覆盖自动翻盖、脚触、润瓷、大冲、小冲、夜灯的开与关。
- 每句按云端 `control_device` 的三种形状打 `/api/frame`：槽位齐全、`parameter_list` 拆成多项、只给 `cmd`。
- 软件半段 80/80 通过。云端模型自己的意图召回和填槽没有在本轮覆盖，原因见第 5 节。
- 一个发现：云端编造的设备号会被本机按原话悄悄换成真实设备，不报错，见第 4 节第 1 条。

## 1 方法

起本机服务，关掉真实 IoT，只让云端路径生效：

```bash
PORT=8911 IOT_MODE=mock IOT_PORT=18911 DEVICE_ROUTE=cloud IOT_FIXTURE=demo node server.mjs
```

对 80 句各做三轮：

| 轮次 | 帧里的槽位 | 验什么 |
| --- | --- | --- |
| 全槽 | `deviceName`、`cmd`、`param`、`value` 齐全 | 云端填对时能不能直接下发 |
| 拆槽 | `parameter_list` 拆成 `{param}`、`{cmd}`、`{deviceName}`、`{value}` 四项 | `mergeParams` 合并后是否等价 |
| 缺槽 | 只给 `cmd` | 本机补 `deviceName`、`param`、`value` 时是否落到选择卡，而不是报缺字段 |

设备按原话的房间和品类从 fixture 里选，优先在线。`switch_water_in` 不在 80 句里，高危确认单独测。

## 3 边界用例

| 用例 | 结果 |
| --- | --- |
| 未接入的函数名 `control_light` | 不进闸门，回 `未接入的意图`，无卡片 |
| `cmd` 不在指令表 `switch_xyz` | 拒绝，理由「指令不在指令表内」 |
| 大冲填 `off` | 拒绝，理由「参数值非法：switch=off，可选 on」 |
| 云端编造设备号 `ARROW_NOT_EXIST` | 不拒绝，按原话收窄后出选择卡 |
| 离线设备下发 | 闸门放行，平台拒绝，卡片记 `FAILED`，播报「设备当前离线，指令已送到平台，这一次没有执行」 |
| 函数回执 `{result:"ok"}` | 识别成回执，`ignored`，不重复执行 |
| 多台同品类、云端没填设备号 | 出选择卡，不自动挑一台 |
| 浴缸进水 | 闸门 `confirm`，等级 H，确认后 `SUCCEEDED`，第二次确认返回「动作已是 SUCCEEDED」 |
| 最终回答里带 `iot` 代码块动作 | 摘动作、过闸、下发，正文只留代码块外的文字 |
| 普通产品问答最终回答 | 不产生卡片，正文原样展示 |

## 4 发现

1. 云端编造的设备号会被静默替换。`src/turn.mjs:160` 的 `chooseDevice` 只判断 `deviceName` 在不在清单里，不在就按原话重新收窄。原话只对得上一台时，直接换成那一台下发。模型填错设备号不会留下任何拒绝记录，只会体现在审计的 `targets` 里。这一层要么在回执里说明「设备号已按原话重选」，要么改成拒绝。
2. 一次函数调用只能带一台设备。`src/frames.mjs:78` 固定返回单元素 `targets`。「把主卫的夜灯和翻盖都打开」这类一句多设备，云端只能调多次或拆句，本机没有合并路径。
3. mock 通过不等于平台通过。fixture 的 `_capabilityNote` 写着真实平台不认 `switch_watering_small`，但当前 `config/scenario.json` 和 fixture 的 `capability` 都还留着这条。小冲 11 句只在 mock 上验过，真机要单独复核。
4. 设备清单有 6000 字上限（`src/roster.mjs:37`）。当前 11 台 2101 字，大约三十台后指令表会被截掉，模型拿不到可选指令。客户设备数上去之前要改成只带相关设备。
5. 纯云端路径下，多台候选时本机仍会出选择卡，不会让模型追问。这是兜底，不是主路径。云端模型按人设会先问哪一台，两条体验不同，验收时要看模型实际走哪条。

## 5 没覆盖的部分

本轮没有接真实房间，所以下面三项没有数据：

- 80 句里云端命中 `control_device` 的比例。
- 云端填出的 `deviceName`、`cmd`、`value` 与预期的差异率。
- 多台同品类时，云端是调用函数还是先追问。

这三项要开一通真实通话，页面逐句发送才有结果。复跑软件半段的脚本在 `/tmp/arrow-cloud-test/run.mjs`，服务起在 8911 即可。

真实房间的结果在 [[2026-11-10-纯云端真实房间/验收]]：80 句 0 次函数调用。
