## 0 这次做什么

不动业务规则：闸门等级、风险阈值、人设、控制台配置、页面交互、`/api` 的对外形状都不改。只补四件事：

1. 一层能跑的 HTTP 接口测试；
2. 四个健壮性洞；
3. 两处结构整理；
4. 注释和文档对齐。

做完之后，运维能照着接口文档单独调任何一步，客户接新产品时改 JSON 不改代码。

不做的：不重构闸门、不引入框架、不加数据库、不改 `.env` 里的密钥。

### 1.1 已经修掉的一条（本次）

`npm run check` 在我改完收窄规则后是红的，三个断言挂在同一个原因上：测试调用 `turn.finish` 时没传 `userText`，新的 `NAMED` 守卫把空原话当成「没点名」，一律先收窄。

处理：测试改成传点名原话，另加一条「没点名时即使模型填了设备号也先收窄」的断言，把两种行为都钉住。

顺带修了 `src/resolve.mjs` 的品类判定：原来把「夜灯」当镜柜的品类提示，`关掉马桶的夜灯` 会只剩 3 台镜柜；改成品类只认设备名说法（坐便器/马桶、浴缸、镜柜），指令能覆盖唯一品类时才用指令定品类。现在各句候选：

| 原话 | 候选 |
| --- | --- |
| 关掉马桶的夜灯 | 6 台马桶 |
| 打开夜灯 | 11 台（没点品类，全给） |
| 来个大冲 | 6 台马桶 |
| 把主卫浴缸进水打开 | 1 台 |
| 客卫冲一下 | 4 台客卫马桶 |

`npm run check` 全绿：`selfcheck ok / turn-gate ok / send-text ok`。

### 1.2 健壮性（四条，按影响排序）

| 编号 | 位置 | 问题 | 建议 | 影响 |
| --- | --- | --- | --- | --- |
| H1 | `src/iot-client.mjs:21` | `fetch` 没有超时也没有重试 | `AbortSignal.timeout(8000)`，5xx 重试一次 | 网关不回包时，一轮会一直挂着，页面只能等 |
| H2 | `server.mjs:117` `readBody` | 请求体没有大小上限 | 超过 64KB 直接 413 | 一个畸形请求就能吃满内存 |
| H3 | `server.mjs:414` `chosenOnce` | Set 只增不减 | 换成 `Map<choiceId, 时间戳>`，10 分钟过期清理 | 长跑内存缓慢上涨 |
| H4 | `src/store.mjs:21`、`src/journal.mjs:19` | 每次读全文件 | 尾读最近 N 行 | `cards.jsonl` 现在 528KB，跑一个月会变成每次请求读几十 MB |

另外两条可选，成本很低：500 日志加请求 id（`server.mjs:427`），`/api/session` 加实例数量上限（`session.mjs` 的 `open`）。

| S2 | `public/app.js` | 999 行无分节 | 按域切六块并加节标题：字幕与气泡、卡片、通话生命周期、发句、设备、审计。函数不动，只挪位置和加注释 |

`src/turn-gate.mjs` 只有一行 re-export，删掉它、让 check 脚本直接 import `../public/turn-gate.js` 更直白。这一改只碰 `src/turn-gate.check.mjs`。

- 80 句语料的回放脚本在 `/tmp/arrow-browser/`，重装就没了。
- `selfcheck` 没覆盖新的 `fill: 'off'` 和 `fill: 'card'` 两种模式。

## 2 第 1 步：API 接口测试

新增 `src/http.check.mjs`，自己起进程、打接口、断言、退出，接进 `npm run check:http`。

| 接口 | 用例 | 断言 |
| --- | --- | --- |
| `GET /api/config` | 默认启动 | `deviceRoute=cloud`、`deviceFill=on`、`deviceCard=false` |
| `GET /api/config` | `DEVICE_FILL=card` 启动 | `deviceFill=card`、`deviceCard=true` |
| `GET /api/devices` | 正常 | `ok=true`，设备数等于清单条数 |
| `POST /api/session` | 未配 BRTC 四件套 | 400，`error` 含「四件套」 |
| `POST /api/frame` | 合法控制帧 | `cards[0].event=demo.gate`，`cards[1].event=demo.result` |
| `POST /api/frame` | 模型填描述而非设备号 | `deny`，`reasons` 含「设备不在该家庭」 |
| `POST /api/frame` | 漏 `deviceName` | `deny`，`reasons` 含「缺少 deviceName」 |
| `POST /api/frame` | 浴缸进水（H） | `demo.gate` 且 `decision=confirm`，有 `pendingId` |
| `POST /api/frame` | 未知函数名 | `parsed.ignored` 或 `未接入的意图` |
| `POST /api/frame` | `[A]` 流式中间态 | 只回 `kind` 与 `partial`，不建卡 |
| `POST /api/choose` | 点第二台设备 | 只下发点的那台，`targets[0].deviceName` 等于它 |
| `POST /api/choose` | 同一 `choiceId` 再点 | 409 |
| `POST /api/choose` | `card` 模式点第一台 | 不再出卡，直接 `demo.gate` |
| `POST /api/confirm` | 确认 `pendingId` | `demo.result`，审计 `trigger=confirm` |
| `POST /api/confirm` | 同一 `pendingId` 再确认 | 400，提示已处理 |
| `POST /api/intent` | 空文本 | 400 |
| 静态 | `/`、`/app.js`、`/style.css` | 200，content-type 正确 |
| 静态 | `../../etc/passwd` | 404 |

把 `contract80.mjs` 收编成 `scripts/replay80.mjs`（只打 `/api/frame`，不开房间），加 `npm run check:replay`。

`accept.check.mjs` 并进 `check`，或明确写进 README 说明它要手动跑。

## 3 第 2 步：健壮性补丁

按 H1 到 H4 顺序改，每条单独一个提交，改完跑 `npm run check`。

- H1：超时 8 秒，5xx 重试一次，重试也失败才返回 `网关不可达`。`selfcheck` 里补一条「网关挂 9 秒仍能返回」的用例，现有的 `hungList` 那条已经覆盖上层，别重复。
- H2：`readBody` 累加字节数，超 64KB 抛错，路由层统一回 413。
- H3：`chosenOnce` 换 Map，写入时记时间，`Date.now() - ts > 10 分钟` 的项在每次写入时顺手清掉。
- H4：`store.tail(n)` 用 `fs.readFileSync` 后从末尾截取，别读全文件；`journal.bySession` 先按 `sessionId` 过滤再解析，解析失败的行跳过。

## 4 第 3 步：结构整理

S1 拆 `server.mjs`。顺序：先把路由表原样搬进 `src/routes/` 四个文件，行为不变，`npm run check` 必须还是绿的；再删 `server.mjs` 里的重复代码。路由的 URL 和响应体一个字都不能改，`/api` 是对外契约。

S2 整理 `public/app.js`。只加节标题、挪函数位置、补函数头一行注释。判断标准：在浏览器里过四条路径不出错——文字发句出卡、语音发句出卡、点击下发、报修卡。

## 5 第 4 步：注释与文档

- `src/turn.mjs` 顶部写清三种 fill 模式的分工和各自跑哪两个函数。
- `src/roster.mjs`、`src/resolve.mjs` 各补一段「为什么这么收窄」，把品类提示和指令品类的关系写进去，这条是本次踩过的坑。
- `README.md` 的模块表和实际文件对齐，`config/scenario.json` 与 `scenario.mjs` 的分工写一句。
- `产品文档/配置参数清单.md` 补 `DEVICE_FILL` 的三个值。

## 6 两套兜底方案

### 方案一：云端 function call（原方案，继续优化）

形状：`DEVICE_ROUTE=cloud`，函数定义按 `产品文档/云端意图配置-新应用.md`，页面用 `DEVICE_FILL=card` 出卡。

下一步优化方向，按性价比排序：

1. 清单裁剪：`src/roster.mjs` 只发当前房间加常用品类的设备，把 2300 字压到 1000 字内，减少模型抓错行。
2. 加 `deviceHint` 参数：模型填「主卫坐便器」这类语义，本机按它收窄，比让它猜设备号稳。改动约 30 行。
3. 函数描述末尾写反例：把「不要反问」「不要只回准备发给平台」写进 `control_device` 的描述，不靠附录。

判据：80 句 + 20 句口语，调用率 ≥ 95%，卡片第一台被点率 ≥ 80%，点名句子的设备落点 100%。

### 方案二：本机占位收窄（泛化兜底）

形状：`DEVICE_ROUTE=local`，ASR 出来后本机判定、本机出卡，云端只负责闲聊和产品问答。

扩展点集中在两个地方，客户接新品时只改这里：

- `src/resolve.mjs` 的 `CATEGORY_HINTS`、`COMMAND_HINTS`：加品类和说法。
- `config/scenario.json` 的 `commands`：加指令、参数、取值和适用品类。

判据：新增一个品类，只改上面两处 JSON 和常量，不动 `policy.mjs`、`turn.mjs`、`server.mjs`。这条要写成一个可复跑的验收：临时加一个假品类，跑一遍，确认不用改其他文件。

两套共用的底座就是第 1 步的接口测试和 80+20 句回放。哪套先跑通看的是同一批指标。

## 7 新窗口交接清单

**开工前**

```bash
git status                       # 确认工作区干净
npm run check                    # 必须全绿，这是基线
```

**顺序**：第 1 步 → 第 2 步 → 第 3 步 → 第 4 步。每步结束跑 `npm run check`，红了就停下来修，不要往下走。

**禁止事项**

- 不改 `src/policy.mjs` 的等级和阈值。
- 不改 `src/turn.mjs` 的闸门顺序（校验 → 风险 → 下发）。
- 不改 `/api` 的路径、请求字段、响应字段。
- 不删 `audit.jsonl`、`cards.jsonl` 的写入。
- 不动 `.env` 和 `.env.example` 里的密钥值。
- 不在代码里加新的第三方依赖。

**验收**

```bash
npm run check          # selfcheck / turn-gate / send-text / 语法
npm run check:http     # 新增，18 条接口用例
npm run check:replay   # 新增，80 句帧回放
```
